# RQM User-Story Functional Requirements

## Purpose

Define the minimum functional requirements for RQM-01 through RQM-21.

| RQM    | Functional Requirements                                                                                       | Architecture                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RQM-01 | Store multiple geometries for one building and select one for analysis.                                       | Use separate `geometries` records. Support points and available 2D footprints; defer 3D geometry. See [ADR-geometry: Recommended starting scope](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-geometry.md#recommended-starting-scope).                                                                                                                                                                                          |
| RQM-02 | Preserve the same asset identity when its information changes.                                                | Use `asset` and `asset_revision` so revisions do not create new assets. See [ADR-versioning: Identity vs revision split](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-versioning.md#1-identity-vs-revision-split)                                                                                                                                                                                                                 |
| RQM-03 | Preserve the source inventory, create project branches, and identify the inventory version used for each run. | Use `inventory_branch`, `asset_revision`, and `versioning` for project versions. Link the approved version to `run_catalog` when used for analysis. See [ADR-versioning: Branches](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-versioning.md#2-branches) and [ADR-versioning: Run immutability](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-versioning.md#5-run-immutability). |
| RQM-04 | Use national, local, commercial, and project inventories while preserving their source information.           | Use `source_registry`, `source_observation`, and `adopted_value_link` to identify each source and trace adopted building data. See [ADR-provenance: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-provenance.md#decision) and [ADR-restricted-sources: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-restricted-sources.md#decision).                          |
| RQM-05 | Represent a building and its identifiable components as related records.                                      | Use `building_components` linked to the building. Component relationships are addressed under RQM-13. See [ADR-citygml-profile: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-citygml-profile.md#decision).                                                                                                                                                                                                              |
| RQM-06 | Produce calculation-ready building data, including the attributes required by different consequence tools.    | Use `export_contract` to define required fields, such as occupancy, stories, foundation, and values. Use `export_product` to record each generated export. See [ADR-exports: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-exports.md#decision).                                                                                                                                                                         |
| RQM-07 | Trace the sources, assumptions, defaults, and transformations applied to building data.                       | Use `source_observation`, `prov_activity`, and `adopted_value_link` to record where values came from and how they were produced. See [ADR-provenance: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-provenance.md#decision).                                                                                                                                                                                             |
| RQM-08 | Associate optional uncertainty with estimated or modeled building attributes.                                 | Store known values on the applicable record. Use `uncertainty_spec` and `uncertainty_ref` only when uncertainty must be represented. See [ADR-uncertainty: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-uncertainty.md#decision).                                                                                                                                                                                       |
| RQM-09 | Trace each result to the asset, hazard, input versions, export, and calculation method used.                  | Use `loss_realizations`, `run_catalog`, `manifests`, `export_product`, and `ddf_library` to preserve the calculation path. See [ADR-exports: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-exports.md#decision) and [ADR-provenance: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-provenance.md#decision).                                                    |
| RQM-10 | Add other infrastructure and hazard types without redesigning the core model.                                 | Use `asset`, `generics`, and `events` as shared structures for new asset and hazard types. See [ADR-citygml-profile: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-citygml-profile.md#decision) and [ADR-generics: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-generics.md#decision).                                                                        |
| RQM-11 | Track parallel edits and compare changes between inventory versions.                                          | Use `inventory_branch`, `asset_revision`, and `revision_log` to separate edits and record each change. See [ADR-versioning: Branches](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-versioning.md#2-branches) and [ADR-versioning: Revision log](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-versioning.md#4-revision-log).                                                      |
| RQM-12 | Capture inventory changes made through GIS software.                                                          | Use `revision_log` to record the edited item, editor, time, reason, and change type. GIS integration can remain application logic. See [ADR-versioning: Revision log](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-versioning.md#4-revision-log).                                                                                                                                                                                 |
| RQM-13 | Represent building components and their relationships for quality control and dependency analysis.            | Use `building_components` and `component_connection` for component records and relationships. See [ADR-citygml-profile: Component connections](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-citygml-profile.md#component-connections--schema).                                                                                                                                                                                    |
| RQM-14 | Represent uncertainty for event-based hazard realizations using appropriate distributions.                    | Use `events`, `hazard_links`, `uncertainty_spec`, and `uncertainty_ref` to connect hazard realizations and uncertainty to affected assets. See [ADR-uncertainty: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-uncertainty.md#decision).                                                                                                                                                                                 |
| RQM-15 | Change an uncertainty distribution or its parameters without redesigning the model.                           | Use `uncertainty_spec` and `distribution_registry` so distributions can be changed through references and parameters. See [ADR-uncertainty: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-uncertainty.md#decision) and [ADR-distribution-registry: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-distribution-registry.md#decision).                           |
| RQM-16 | Record who changed an inventory, when the change occurred, and why it was made.                               | Use `revision_log` and `prov_agent` to record the editor, time, reason, and change details. See [ADR-versioning: Revision log](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-versioning.md#4-revision-log).                                                                                                                                                                                                                        |
| RQM-17 | Support reusable continuous and categorical uncertainty definitions.                                          | Use `uncertainty_spec`, `uncertainty_spec_continuous`, `uncertainty_spec_categorical`, and `uncertainty_ref` to define uncertainty once and reuse it. See [ADR-uncertainty: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-uncertainty.md#decision).                                                                                                                                                                      |
| RQM-18 | Support future exports to richer schemas such as CityJSON or 3DCityDB.                                        | Use `export_contract`, `geometries`, and `component_connection` to preserve an export path without implementing the exporter now. See [ADR-citygml-profile: RQM-18 escape hatch](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-citygml-profile.md#rqm-18-escape-hatch--cityjson--3dcitydb-export).                                                                                                                                 |
| RQM-19 | Prevent restricted information from appearing in public exports while preserving source traceability.         | Use `source_registry`, `source_observation`, and export access rules to classify and exclude restricted information. See [ADR-restricted-sources: Decision](https://github.com/fema-ffrd/rqm-data-model/blob/feature/hybrid_data_model/docs/decisions/ADR-restricted-sources.md#decision).                                                                                                                                                                                         |
| RQM-20 | Provide traceable risk information for Benefit-Cost Analysis.                                                 | Use `asset`, `events`, `mv_loss_summary`, and `export_product` for risk results. Support project cost and baseline-versus-mitigation loss comparison.                                                                                                                                                                                                                                                                                                                              |
| RQM-21 | Provide asset, hazard, loss, uncertainty, and metadata outputs for insurance and actuarial analysis.          | Use `asset`, `events`, `mv_loss_summary`, and `export_product`.                                                                                                                                                                                                                                                                                                                                                                                                                    |
